地圖繪製層:四個入口的架構與掛入方式

四個入口：/ai-plan 手機、/ai-plan 桌面、登入後手機、登入後桌面。每個入口都是同一組分層：Content（狀態擁有者）→ PlanLayout（容器）→ PlanOverlayLayout（地圖層加疊加層外殼）→ LivePlanLayer（規劃面板接線）→ PlanMap，同名元件放在 web/src/planning/ 底下的 preview/、member/phone/、member/desktop/（2026-10-24 目錄重整，見下方「planning/ 目錄結構」）。/ai-plan 的手機與桌面是同一個 Content，靠 isDesktop 與 isWide 切版面；登入後的手機與桌面入口不同（planning/member/phone/Content、planning/member/desktop/Content），但包的是同一個 PlanMap。四個入口的地圖底座都是 NativeMapBase，站點圓點等繪製都經統一繪製層；後端查詢走注入的資料存取層 PlanAiDataSource。這一頁以圖與表為現況，最下方的變更紀錄是歷史。內容依程式碼整理，沒有在瀏覽器實測。

/ai-plan 手機地圖元件 PlanMap 掛圖層,頁面只持有狀態

planning/preview/Content 持有狀態、傳 prop 給地圖元件 PlanMap(與登入後的 PlanMap 同名、同層級,各自實作)。PlanMap 用 NativeMapBase 建圖（推論態的 children 是 ExploreControls：「探索」與「搜尋這個區域」按鈕），經 usePlanMapDrawing 掛 useSharedDrawLayer：currentLocationLayer 一律掛；planStopLayer、transitHoverLineLayer、routeLineLayer 因為有 stopDots 都放進 layers（整條路線只在 enabled 時畫）；attractionGlowLayer 因為恆傳 attractionGlow 而掛，但景點清單在非推論態是空的所以沒有東西可畫；tripEntryLayer、searchResultLayer 在 /ai-plan 不傳資料所以不掛。MapHandle 經 PlanMap 內的 useMapHandle 回報給 Content（安全區平移用）。NativeMapBase 傳 center（由 initialCenter 經 resolveMapCenter 轉出）、zoom、mapId、theme（只收 dark / light，日夜切換時重建地圖）、onHandleChange（加 children），沒有傳 onPoiClick。光暈資料（景點區域加「探索」控制項）來自獨立 hook useAttractionGlow。

/ai-plan 桌面同一個頁面元件,圖層掛法與手機相同

桌面與手機都是 planning/preview/Content,地圖由 PlanMap 渲染並掛 useSharedDrawLayer(含光暈),圖層完全相同;差別只在 isDesktop、isWide 決定的版面與鏡頭行為(綠色框)：桌面又分 wide（≥1024px，有安全區節點）與非 wide（768–1023px，沒有安全區節點）；兩者點選圖卡都會平移，差別只在落點（安全區中心或直接 panTo）。桌面不做首站自動平移。

登入後手機PlanMap 是 NativeMapBase 加一組掛載式 hook

站點檢視與面板開關（chatSheetOpen）在 planning/member/phone/Content；地圖相關的狀態（usePlanningState、useMapState、目前位置、首站平移）在 PlanPhoneView，它再把值傳進 PlanMap。PlanMap 用 NativeMapBase 建圖,查詢、事件、平移、點擊分流各由獨立 hook 負責;舊的完整實作 PlanMapLegacy.tsx 已刪除(2026-10,沒有任何檔案引用)。圖一畫狀態、UI 層與圖層(含統一繪製層與 google.maps.Map);抽出的 hook 兩邊共用,畫在頁面下方的「登入後共用」區塊。

登入後共用PlanMap 抽出的狀態與事件 hook

登入後手機與桌面是同一個 PlanMap，它用這 8 個 hook：useMapHandle、useMapViewport、useMapIdle、useExploreQueries、useAttractionClickRouting、useFitToGeocodeResults、usePanTarget、usePlanMapDrawing。/ai-plan 的 PlanMap 也用其中的 useMapHandle、useMapViewport、useMapIdle、useExploreQueries（加 ExploreControls 的按鈕）和 usePlanMapDrawing：景點查詢同樣是按「探索」才查、移動後按「搜尋這個區域」重查，不再 idle 後自動查；/ai-plan 沒有的是 usePanTarget、useAttractionClickRouting、useFitToGeocodeResults，以及搜尋框與類別標籤。這一塊是各裝置圖一左欄「其餘掛載式 hook」的展開；箭頭上的字是傳遞的值。

站點圓點、藍點、路線、虛線、行程 entry、搜尋結果、光暈都走統一繪製層，由宿主依 mapVersion 統一處理地圖重建；登入後的 PlanMap 不重建地圖（rebuildOnThemeChange=false），目前不影響。useMapViewport、useMapIdle 有 mapVersion 參數：登入後的 PlanMap 沒傳，/ai-plan 的 PlanMap 有傳。

新架構統一繪製層:功能層組合在同一個宿主裡

地圖上原生繪製的東西(marker、圓圈、線)由同一層管理。功能層是純函式,只把資料轉成「要畫什麼」;宿主 useMapDrawLayer 負責組合、依 id 比對、畫出、疊放順序、地圖重建後重掛與清理。程式在 planning/map/draw/(原 geo-planning/mapDrawLayer/)。功能層共七個,在 planning/map/draw/layers/:planStopLayer(行程站點圓點)、currentLocationLayer(藍點)、routeLineLayer(整條路線)、transitHoverLineLayer(轉乘 hover 虛線)、tripEntryLayer(行程 entry 旗子)、searchResultLayer(搜尋結果標記)、attractionGlowLayer(景點光暈),全部由共用子層 useSharedDrawLayer 組合;原本只給 itineraries 詳情頁的 routePolylineLayer 已在 2026-10-24 併入 routeLineLayer;attractionGlowSupport.ts 是光暈的支援檔(照片排程與標籤避讓的 hook),不是功能層。七個共用功能層加宿主呼叫與強調色讀取（useAccentColor）收在共用子層 useSharedDrawLayer，呼叫它的接線處有四個：登入後的 PlanMap（planning/map/PlanMap.tsx）、/ai-plan 的 PlanMap（planning/preview/PlanMap.tsx）、行程詳情頁的 PlanMap（itineraries/PlanMap.tsx，站點圓點走 planStopLayer、連線走共同的 routeSegments prop）三者都經 planning/map/planMapShared.ts 的 usePlanMapDrawing；首頁展示頁 InteractiveExploreMap 直接呼叫，只傳 attractionGlow。useSharedDrawLayer 仍保留選填的 extraLayers，但目前沒有接線處傳。宿主支援 marker、circle、polyline、overlay 四種繪製項目；marker 一律用 AdvancedMarkerElement，所以掛宿主的地圖都必須帶 mapId（行程詳情頁用 SIMPLE_MAP_ID）。2026-10-24 補充：planStopLayer 的點除了站點與主題點，現在也畫旅館（PlanStopMarker.lodging，床 glyph，不參與 routeLineLayer 的線段）；主題點的子景點小點與旅館點的座標都來自執行時解析結果（planning/data 的共用 store，經 PlanDataProvider.tsx 的 useResolvedRefs 取用），不是節點上的快照；三個連線功能層改畫弧線加光暈（routeArc.ts、routeStyle.ts，見下方「連線樣式」）。

項目現況為什麼
弧線相鄰兩站之間是一條二次貝茲弧線,取樣 ARC_SEGMENTS = 16 段;最大偏離量 = 弦長 × ARC_SAG_RATIO(0.12);弦長不到 ARC_MIN_METERS(40 公尺)直接畫直線。一律往行進方向的左側鼓起直線像尺規畫的。比例式的偏離量讓長段與短段一樣「彎」;固定往左鼓,A→B 與 B→A 的來回兩段會鼓向兩側、不重疊;太短的段彎了也看不出來,省取樣點
為什麼在世界座標算在 Web Mercator 的 0..1 平面(與縮放無關)算垂直方向,再轉回經緯度(projectMercator / unprojectMercator,純算術,不碰 google.maps)Polyline 在投影平面上連直線,經緯度在高緯度被拉伸,直接在經緯度算會讓弧線歪斜、不同城市長得不一樣

方向箭頭白色開口 chevron(SymbolPath.FORWARD_OPEN_ARROW),scale 1.7、線寬 1.6、透明度 0.9,每 ROUTE_ARROW_REPEAT 150px 一個,起點偏移 50%(短段至少中間一個)只是提示方向,不搶視覺;單位都是螢幕像素,任何縮放看起來一樣
