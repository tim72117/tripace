## 0. 問題與方向

現況:4 層同心橢圓階地(blob)疊高,再加北側一道弧形山壁,外形接近圓。從封面鏡頭看是一圈一圈的環,像環形山或結婚蛋糕。

真實九份的樣子(以下是一般印象,不是測量資料):
- 九份蓋在基隆山西側山腰上,面向海,是一整面往下傾的山坡,不是圓錐。(憑印象:實際朝向大約是北到西北,面對深澳、基隆嶼那一側的海)
- 基山街(老街)大致沿著等高線橫向走,彎彎曲曲,兩側店屋貼在一起。
- 豎崎路是一條垂直於坡面的長石階,和基山街、輕便路十字交叉,兩旁屋簷與紅燈籠夾道。
- 房子蓋在削平的小平台上,一排一排沿等高線疊上去,屋頂層層往下看得到海。
- 背後是山。基隆山是一座獨立、圓錐形的山,在九份東側。(憑印象)

設計方向:**一整面朝海傾斜的山坡**。等高線大致是東西向的橫線,中間微微往海鼓出;街道沿著等高線走,石階垂直爬坡;房子放在一條一條沿等高線的小平台(pad)上;背後一道主稜,東側高起基隆山;兩側各有一道山溝把山城和旁邊的山體分開;前緣是低平的海岸帶。

**方位約定**:為了讓封面鏡頭(在 +z,南方)正對山城,本設計把「海」放在 +z(南)、「山」放在 −z(北)。這和真實方位(九份面北)不同,屬於刻意旋轉,文件和程式註解都要寫明。

## 3. 高度場配方

### 3.1 全域設定

| 欄位 | 值 | 說明 |
|---|---|---|
| `topY` | **−2.5** | 高度場低於它的地方一律夾在 −2.5,就是海岸的底(沙灘)。現在是 0,要改 |
| `sea.y` | −3.5 | 不變,沙灘比海面高 1 格 |
| `thickness` | 7 | 不變,島底在 −9.5 |
| `terrain.cell` | 1.5 | 預設 2 也能用;石階切溝、pad 邊緣在 2 格網格下會有點鈍,建議先試 1.5 |

### 3.2 ramp(基底斜面)

```ts
ramp: { from: [0, 34], to: [0, -30], y0: -3, y1: 17 }
```

從前緣海岸(z=34,y=−3)一路升到背後(z=−30,y=17),坡度 20/64 ≈ 0.31(約 17°)。方向純南北,所以基本等高線是東西向的橫線,街道沿 x 方向走就會自然貼著等高線。z<−30 夾在 17,交給主稜和背坡處理。

### 3.3 features(bump / ridge,依序列出,疊加順序無關)

```ts
features: [
  // F1 後山主稜:由西往東升高,東側接到基隆山。halfWidth 11 讓稜線寬而圓,夜裡是一條柔和的剪影
  { kind: 'ridge', points: [[-46, -22, 4], [-30, -27, 8], [-14, -27, 7], [2, -27, 9], [14, -25, 12], [24, -22, 14], [34, -17, 9], [46, -12, 3]], halfWidth: 11 },
  // F2 基隆山:主稜上再疊一個圓錐狀隆起,山頂實際高度約 35(憑印象:基隆山在九份東側、形狀渾圓)
  { kind: 'bump', x: 26, z: -21, rx: 11, rz: 10, height: 7 },
  // F3 北側背坡:負高度的山脊沿著背緣外側走,讓島的後緣往下收,背面切面從約 25 降到 14~18
  { kind: 'ridge', points: [[-44, -30, -8], [-20, -36, -12], [4, -37, -12], [26, -35, -10], [44, -24, -6]], halfWidth: 9 },
  // F4 山城所在的緩凸山腰:等高線在中央往海面微微鼓出,避免整面坡像一張平板
  { kind: 'bump', x: -4, z: 4, rx: 26, rz: 20, rot: 0, height: 2.2 },
  // F5 西側山溝:從山上斜斜往西南海灣下去,最深處約 −4.5,分開山城與西側山體
  { kind: 'bump', x: -36, z: 8, rx: 9, rz: 22, rot: -0.35, height: -4.5 },
  // F6 東側溪谷:比西側深,分開山城與基隆山山腳,出口在東側小灣
  { kind: 'bump', x: 33, z: 6, rx: 9, rz: 20, rot: 0.3, height: -5 },
  // F7 茶樓小岬:茶樓所在的觀景肩,讓茶樓台地前緣略微凸出
  { kind: 'bump', x: -17, z: -14, rx: 9, rz: 7, rot: 0.2, height: 1.5 },
  // F8 豎崎路切溝:石階嵌進山坡,兩側地面比石階略高,屋簷夾道。中段最深 −2
  { kind: 'ridge', points: [[6, 14, -0.6], [6, 9, -2.0], [6, 4, -1.4], [6, 1, -0.4]], halfWidth: 4.5 },
  // F9 輕便路路塹:緩坡小路切進山腰,北側(上坡側)自然形成一道土坎,剛好配模型的擋土石牆
  { kind: 'ridge', points: [[3, -1.5, -1.0], [-1.5, -3.6, -0.7], [-6, -5.7, -0.2]], halfWidth: 3 },
  // F10 前緣中央小岬:海岸線中段微微隆起,沙灘不會一整條平板
  { kind: 'bump', x: 12, z: 30, rx: 7, rz: 4, height: 1.2 },
]
```

F8、F9 這兩條負高度山脊是必要的:不加的話,原始坡面在石階和輕便路中段會比模型的踏面高 0.8~1.5 格,地面會穿出階梯。加了以後,沿石階中線的地面全程低於踏面 0~1.5 格(階梯是實心方塊,下面不會露空),兩側離中線 3 格處的地面則與踏面大致齊平。

### 3.4 noise

```ts
noise: { amp: 0.7, scale: 9, seed: 7 }
```

低頻微起伏,只是讓坡面不要像塑膠板。pad 內不受影響。引擎只支援一組 noise;如果之後想讓山稜更崎嶇,建議另外加幾個小 bump,不要把 amp 調大(amp 大了,pad 的切填量會跟著變大)。

## 9. 風險與取捨

### 9.1 憑印象、刻意風格化的部分

- **方位**:真實九份大約面北到西北,這裡把海放在南方(朝鏡頭)。
- **高度順序**:真實的輕便路在基山街**下方**,阿妹茶樓大約在豎崎路中段、靠近輕便路一帶,不是全區最高點(憑印象)。這裡依文章順序與「茶樓是終點與視覺頂點」的需求,改成高度遞增。如果之後想更寫實,替代方案是:基山街放中段,石階往**下**接到輕便路,茶樓放在石階中段的肩上,但這樣旅人會一路下坡,終點也不再是最高點,和目前的演出節奏衝突,所以本版不採用。
- **基隆山**的位置(東側)與形狀(渾圓錐形)、兩側山溝、海岸是沙灘還是礁岸,都是憑印象。真實九份下方是水湳洞、深澳一帶,不是直接下到沙灘。
- **豎崎路和基山街十字交叉**是印象中的經典畫面;這裡讓石階從基山街往上出發(T 字),沒有往下延伸。如果要做十字,可以在 P2 南側再接一段往下到 R1b 的短石階(scale 6、爬升約 2.6)。

### 9.2 需要看畫面再調的數值

1. **ramp 坡度(0.31)**:太緩會像平板,太陡會讓 pad 的切填超過 2 格、土坎太多。如果看起來太平,先把 y1 從 17 調到 19,再把所有 pad 的 y 重新取原地形平均(見 9.3)。
2. **F4 山腰凸度(2.2)**:等高線鼓出的程度。太大會讓基山街看起來像繞著山頭走。
3. **F8 切溝深度(−2.0)**:石階兩側土坎的高度。太深,石階會像埋在溝裡;太淺,地面會穿出踏面(低於約 −1.2 就會穿)。
4. **基隆山高度(約 35)**:封面上可能搶戲。可以降到約 30(F2 height 改 2),或靠夜色壓暗。
5. **P6 茶樓台地的北側切坡(2.8)**:如果背後的土坎太突兀,可以把 F7 的 height 從 1.5 降到 0.5,或把 P6 的 blend 加到 4。
6. **屋排數量與間距**:目前 15 條屋排的總長約 200 格,配上每 3~4 格一棟,大約 60~70 棟。不夠密的話,先補短的屋排(深 3、長 6~8),不要把現有屋排加寬。
7. **terrain.cell**:1.5 或 2,要看效能。
8. **海岸帶寬度**:z 24~34 約 10 格寬的平地,前景可能太空,可以把 outline 前緣整體往北收 2~3 格。

### 9.3 改參數後的維護方式

只要改了 ramp 或任何 feature,所有 pad 的 y 都要重新對齊原地形。建議在 layout.ts 用程式算,不要寫死:

- 每塊屋排 pad 的 y = 範圍內原地形(`baseFieldAt`)的平均值,取到小數 1 位。
- 站點 pad(P2/P3/P5/P6)的 y 維持手寫,因為它們要和石階爬升量(0.43 × scale)對齊:P3 = P2 + 6.02(四捨五入到 9.4),P6 = P5 + 3.01。

建議另外寫一支測試(`scenes/night-jiufen/terrain.test.ts`):
- 每個站點的 y 等於 heightAt(x, z)(誤差 0.05 內)。
- 石階與輕便路沿中線每 0.5 格取樣,heightAt ≤ 踏面高度 + 0.05。

### 10.6 石階模型的擺法(往上走、往下走都適用)

- 模型的 (x, z) 是**石階長度的中點**;y 是**最低一階的底面**高度。最低一階在模型 local +Z 端(z = +0.5),往 −Z 爬升,每 1 scale 爬 0.43。
- 世界座標:rotY = atan2(−dx, −dz),(dx, dz) 是**上坡方向**。最低一階的位置 = 中點 + (scale / 2) × (sin rotY, cos rotY);最高一階 = 中點 − (scale / 2) × (sin rotY, cos rotY)。
- **旅人走的方向和模型朝向無關**。模型永遠讓 −Z 朝上坡;旅人下坡,就是步道折線從最高一階的位置往最低一階的位置走。
- 豎崎路:中點 (6, 8)、rotY 0、y 3.4 → 最低一階在 z 15(y 3.4),最高一階在 z 1(y 9.42)。旅人路徑是 z 1 → 15,腳底 y = 3.4 + (15 − z) × 0.43,從 9.42 遞減到 3.4。
- 小石階:中點 (−8.6, 9.5)、rotY 0、y 4.9 → 最低一階在 z 12(y 4.9),最高一階在 z 7(y 7.05)。旅人路徑是 z 12 → 7,往上走。
- 輕便路模型同理:最低端 = 中點 + 5 × (sin 1.134, cos 1.134) = 中點 + (4.53, 2.13)。

6. **建議的測試**(補進第一版提的 `terrain.test.ts`):
   - 豎崎路、輕便路、小石階沿中線每 0.5 格:底面 − 0.05 ≤ heightAt ≤ 踏面 + 0.05。

### 11.1 外觀(憑印象,不是考據)
