# 精選景點關聯性案例研究

> `research-*` 一次性研究快照（2026-08）。若後續定案要實作資料模型/API，另開 `refactor-*` 規劃承接，本文保留不動。

## 1. 背景與目的

「精選景點」功能的資料模型設計，需要先回答一個問題：精選點之間的**關聯性**該怎麼表達？在前期討論中列出三種候選方向：

- **A. 父子關聯**（`parentId` 指向主地標）——單層樹狀，改動最小。
- **B. 鬆散分組**（`groupId`/策展主題標籤）——平輩關係，一個地點可屬多個群組，但需要先確認「這批地點是否真的有值得策展的故事性」才值得做。
- **C. 純地理鄰近**（不存關聯欄位，查詢時依距離動態算）——最省事，但關聯是隱性、脆弱的，無法表達「為什麼精選」。

使用者傾向 B 或 C，但要求先做案例研究，確認哪些鄰近地景之間**真的**有值得產生關聯的故事性，才值得投入 B 這種策展成本；同時要求呈現方式必須同時做到「讓使用者一眼看出鄰近關係」與「說得出精選原因」。本文即為這項案例研究的完整記錄，範例錨點沿用最初提出的「京都清水寺周邊（產寧坂/二年坂/三年坂一帶）」精選店家清單。

**方法**：兩輪調查。第一輪聚焦清水寺案例本身與泛用判斷準則；第二輪擴充到日本以外（含一個刻意找的反例）與台灣本土案例，驗證判斷準則是否能泛化、並具體評估「若要做，台灣哪些地區適合、該怎麼命名策展主題」。

## 2. 其他旅遊/地圖產品的組織方式（三種模式並存，用途不同）

- **Google Maps「Lists」**：使用者/編輯自建清單，性質是「無序、平輩並列的主題清單」——地點沒有先後順序，只有「同屬一個收藏主題」的關聯，可加註記說明為何收錄。最貼近「策展但不敘事」的模型。
- **TripAdvisor「Travelers' Choice / Best of the Best」**：演算法+評分排名清單，是「附近推薦」與「熱門排行」的混合，不強調地點間敘事關聯，只強調「這些各自很好」。
- **るるぶ、そうだ 京都、行こう。等日本旅遊雜誌/官方觀光網站**：一致採用「有順序、有敘事的散策路線（モデルコース）」，例如「從八坂神社出發 → ねねの道 → 高台寺 → 八坂の塔 → 二年坂 → 一年坂 → 三年坂（産寧坂）→ 清水寺」，並明確標註步行節奏建議。屬於**有方向性、有節奏設計**的路線敘事，而非單純清單。

三者對照：Google Maps List 是「使用者自己策展的收藏」、TripAdvisor 是「群眾統計出的排名」、日本觀光媒體是「編輯部設計的散策動線」——**只有第三種真正在做「有共同主題＋有順序敘事」的路線規劃**，前兩種都是平輩清單或排名，不表達地點間的先後關係。

## 3. 清水寺案例：關聯性從何而來

- **同一條連續參道系統**：產寧坂（三年坂）、二年坂（二寧坂）、一念坂本來就是清水寺參拜道的延伸，三者首尾相連、地理上是**同一條坡道動線的三段**，命名彼此還有典故關聯（三年坂的安產信仰傳說衍生出二年坂、一念坂的命名）。不是「剛好距離近」，而是**同一條路的不同路段**。
- **共同的法定文化保存範疇**：這一帶被指定為「産寧坂重要伝統的建造物群保存地区」（1976 年指定，8.2 公頃，性質分類為「門前町」），官方保存計畫細分為五個子區。
- **共同的門前町商業文化脈絡**：茶屋、湯豆腐、工藝品店群聚於此，歷史成因是清水寺參拜人潮帶來的門前町商業聚落，性質類似淺草仲見世通り之於淺草寺、巢鴨地藏通商店街之於高岩寺——**都是「因參拜動線而生的商業街」，不是隨機群聚的店家**。
- **七味家本舖的動線角色**：位在清水坂與產寧坂交會處，從哪個方向爬坡都會經過，具有明確的**動線節點/入口地標**角色，適合作為「路線起點」而非單純「附近一家店」。
- **體驗互補性**：忠僕茶屋（境內）→ 順坡道下來依序遇到 CHASEN、%ARABICA（休憩）與奧丹/順正（正餐）、七味家/松韻堂/朝日堂（伴手禮），天然形成「參拜→休憩→用餐→採買」的節奏，與坡道由上而下的實際步行順序吻合。

## 4. 泛用判斷準則（四項）

滿足 2 項以上視為值得策展的強關聯：

1. **共享物理動線**：地點位於同一條連續道路/參道/坡道上，步行間有自然先後順序。
2. **共享法定或歷史認定範疇**：同屬一個文化保存區、同一門前町、同一歷史街區指定範圍。
3. **共享起源敘事**：因同一個核心地標的人潮而歷史性群聚形成，可用一句話講清楚「為什麼會在這裡」。
4. **體驗節奏互補**：類型上有自然承接關係（如參拜→小吃→伴手禮），適合連續體驗而非平行選項。

**不該過度關聯的信號**：地點分屬不同動線僅因演算法半徑內被歸類；除了座標外沒有共同歷史/商業/文化敘事可陳述；地點屬於不同主題/客群導致動線邏輯衝突；地點之間是**競爭/替代關係**而非**互補/接續關係**（見下方北投案例）。

## 5. 擴充案例：日本以外

### 5.1 德國 Rothenburg ob der Tauber 市集廣場（歐洲老城廣場型）

1170 年建城，1274 年獲「帝國自由市」地位，靠布料/鹽/酒貿易致富，行會圍繞市集廣場組織。

| 準則 | 強度 |
|---|---|
| 共享物理動線 | 弱–中（廣場輻射型，非單一坡道，走法是「逛整區」而非「走一條路」） |
| 共享法定/歷史認定範疇 | 強（城牆圈定的舊城本身即受保護的歷史核心區） |
| 共享起源敘事 | 強（同一波中世紀貿易繁榮與行會制度催生） |
| 體驗節奏互補 | 中（市政廳/教堂/行會屋功能互補，但非消費節奏設計） |

**小結**：3/4，但結構是「廣場放射」而非「線性路線」——提醒策展分組不必都套線性敘事，也可以是「以某個核心廣場/地標為圓心的區塊型分組」。

### 5.2 朝聖之路 Camino de Santiago（歐洲朝聖路線型）

9 世紀起朝聖者步行前往聖地牙哥，沿途小鎮（如兩條路線匯流的 Puente la Reina）因朝聖人流而興起。

| 準則 | 強度 |
|---|---|
| 共享物理動線 | 極強（同一條路的不同段落，本身就是「一天一段」的順序設計） |
| 共享法定/歷史認定範疇 | 強（UNESCO 世界遺產、歐洲理事會第一條認定文化路線） |
| 共享起源敘事 | 極強（每個城鎮存在理由就是服務朝聖者） |
| 體驗節奏互補 | 強（走路/投宿/用餐/禮拜的日節奏即路線設計） |

**小結**：4/4，判準最乾淨的滿分案例，但規模是跨城市多日路線，性質更接近「行程規劃」而非「單一地標周邊」——可作為未來若要做「多日健行/朝聖路線」策展模組的參照，非清水寺這種「單日單街區」的對照組。

### 5.3 泰國清邁古城寺廟群（亞洲寺廟商街型，中等關聯對照）

1296 年蘭納王國建都，護城河圍出方形古城，30 餘座寺廟在其後六百年陸續建成，古城內傳統寺廟與現代咖啡館混雜。

| 準則 | 強度 |
|---|---|
| 共享物理動線 | 中（棋盤格街道，寺廟分散，有推薦路線但非單一天然坡道） |
| 共享法定/歷史認定範疇 | 中（古城牆是歷史範圍，但區內店家未必個別受保護） |
| 共享起源敘事 | 中強（同源於蘭納王朝建都與宗教建設史） |
| 體驗節奏互補 | 弱–中（新舊混雜，寺廟與商店關係更像「疊加」而非門前町） |

**小結**：約 2.5/4，中等關聯——建議做法是**按子區域分組**（如某座寺廟周邊 200 公尺內店家）而非把整個古城當一條敘事路線，範圍太大會稀釋關聯強度。

### 5.4 反例：加拿大 Niagara Falls「Clifton Hill」（純人流導向商業帶）

1830 年代僅為靠近瀑布的旅館用地，1920 年代起業者發現瀑布人潮商機才陸續進駐，1960 年代起蠟像館、鬼屋、金氏世界紀錄博物館等**各自獨立進駐、彼此無關聯**。

| 準則 | 強度 |
|---|---|
| 共享物理動線 | 僅表面（同一條街，但純粹因為是「離瀑布最近的路」） |
| 共享法定/歷史認定範疇 | 無（無歷史街區指定，純民間商業地產陸續轉手開發） |
| 共享起源敘事 | 無（蠟像館/鬼屋/電動遊樂場彼此沒有共同故事，只是各自看中同一批遊客） |
| 體驗節奏互補 | 無，甚至互斥（多間同類型景點是競爭而非互補，去一間不會自然導向去另一間） |

**小結**：**0/4**——教科書級的「純距離鄰近、不該過度策展」案例。關鍵判斷信號：**這些店家共享的是「同一個人流來源」，而不是彼此之間的關係**。若包裝成「精選路線」會是失真的策展，正確做法是保持「附近推薦」的鄰近清單，不強加敘事。

## 6. 擴充案例：台灣

### 6.1 艋舺龍山寺周邊（剝皮寮、華西街）——廟宇老街型，但關聯較破碎

龍山寺是泉州移民集資興建的信仰核心；剝皮寮起源是清代「杉木剝皮加工區」；華西街源於艋舺的紅燈區（遊廓）歷史，後轉型為夜市。三者地理相鄰（步行 3-5 分鐘），但**各自起源敘事並不相同**，只是同屬「艋舺」這個大範圍。

| 準則 | 強度 |
|---|---|
| 共享物理動線 | 弱–中（鄰近但非同一條線） |
| 共享法定/歷史認定範疇 | 中（各自是市定/國定古蹟，但無涵蓋三者的單一法定街區） |
| 共享起源敘事 | 弱（三個不同歷史身份：信仰核心、加工老街、庶民風化區） |
| 體驗節奏互補 | 中（參拜→老街展覽→夜市小吃作為一日行程順序合理，但非歷史必然性） |

**小結**：約 1.5-2/4，中等偏弱，且關聯是拼接式而非有機的。

**命名建議**：**不適合**模仿清水寺「XX老街散策」的單一坡道敘事，這裡沒有一條貫穿的物理/敘事主軸。較適合「艋舺歷史踏查」「萬華百年風貌」這類**承認多重身份堆疊**的框架，或拆成三個各自獨立的小分組（信仰/產業/庶民生活），不硬湊成一條路線。

### 6.2 鹿港老街（天后宮、瑤林街、埔頭街、龍山寺）——廟宇老街型，強關聯

天后宮（明萬曆年間，近 400 年）為信仰與商業匯集核心；瑤林街、埔頭街是清代「一府二鹿三艋舺」鹿港對渡貿易大港時期形成的街屋群，緊鄰天后宮；遊客動線明確是「中山路→天后宮參拜→沿瑤林街、埔頭街往南逛老街」。龍山寺（清乾隆遷建，國定古蹟）在稍遠處，屬延伸行程。

| 準則 | 強度 |
|---|---|
| 共享物理動線 | 強（天后宮到瑤林街/埔頭街是連續動線，與清水坂結構相似） |
| 共享法定/歷史認定範疇 | 強（老街整體風貌保存區＋個別古蹟身份） |
| 共享起源敘事 | 強（同源於清代鹿港對渡貿易繁盛期） |
| 體驗節奏互補 | 中強（參拜→老街糕餅工藝店漫遊，龍山寺因距離稍遠可作次一層分組） |

**小結**：3.5-4/4，是台灣**最貼近清水寺案例結構**的地點。

**命名建議**：適合直接套用「XX老街散策」句式，例如「鹿港天后宮老街散策」，核心路線收斂在天后宮＋瑤林街／埔頭街；龍山寺因距離較遠，建議列為「延伸行程」子分組而非塞進同一條路線，避免稀釋動線的緊密度。

### 6.3 迪化街／大稻埕——非廟宇型態，強關聯但敘事主軸不同

1850 年代艋舺泉州移民形成「中街」，1860 年淡水開港後大稻埕以茶葉/布料貿易繁盛，發展出南北貨/中藥/布匹三大批發產業，霞海城隍廟是周邊信仰中心，但**街區成因主軸是貿易機能，不是參拜動線**。

| 準則 | 強度 |
|---|---|
| 共享物理動線 | 中強（南街-中街-北街是連續老街，但性質是批發商業街） |
| 共享法定/歷史認定範疇 | 強（台北市歷史風貌特定專用區，都市計畫層級的法定保存） |
| 共享起源敘事 | 強（所有店家共享「大稻埕貿易港」單一起源） |
| 體驗節奏互補 | 中（南北貨/中藥/布匹＋近年文青咖啡店，節奏是「選物」而非參拜節奏） |

**小結**：3.5/4，關聯強，但**敘事性質是貿易史，不是宗教參拜**。

**命名建議**：不宜套清水寺式的參道敘事語感，較適合「大稻埕南北貨風華路線」「迪化街貿易老街踏查」這類強調商業/貿易史的命名，讓策展主題貼合實際成因，而非套用統一模板。

### 6.4 北投溫泉區（新北投）——溫泉區型，關聯結構特殊

1896 年天狗庵開創台灣第一家溫泉旅社，此後旅館圍繞北投公園、地熱谷因**溫泉資源本身**而非單一地標人潮群聚而成。

| 準則 | 強度 |
|---|---|
| 共享物理動線 | 中（商圈範圍明確但非單一參道，是圍繞公園的區塊） |
| 共享法定/歷史認定範疇 | 中（市府劃定商圈，非文資法定街區） |
| 共享起源敘事 | 中強（同源於溫泉資源開發，但旅館彼此是「同業競爭」關係） |
| 體驗節奏互補 | 弱（旅館之間是**替代關係**——消費者通常只選一家泡湯，不像清水寺周邊店家是互補消費） |

**小結**：約 2/4，中等，但**結構性質特殊**：這是少數「地點彼此是競爭選項而非互補動線」的案例。

**命名建議**：不適合「散策路線」框架，旅館本身應以 Google Maps List 式的「平輩比較清單」呈現（如「北投溫泉旅館精選」）；若要做敘事路線，應鎖定非住宿類地標（北投公園、地熱谷、溫泉博物館、北投車站）做「北投溫泉歷史散策」，把「選旅館」和「逛歷史動線」拆成兩種不同性質的策展物件，不要混在一起。

## 7. 跨案例觀察

- 「共享法定/歷史保存範疇」幾乎是所有強關聯案例（Camino、鹿港、迪化街、清水寺）的共同要素，可作為判斷「值得策展」的較強訊號之一。
- 反例（Clifton Hill）與北投溫泉都提醒：**同一個人流來源（地標/資源）不等於彼此有關聯**——尤其當地點之間是「競爭/替代」而非「互補/接續」關係時，即使物理上緊鄰，也不該包裝成單一敘事路線，而應保留為平輩清單或鄰近推薦。
- 敘事主軸不必千篇一律套「XX老街散策」——貿易型（迪化街）、信仰參拜型（鹿港、清水寺）、多重身份堆疊型（艋舺）、資源導向型（北投）、廣場放射型（Rothenburg）、多日路線型（Camino）應該用不同的命名語感和分組粒度來表達。
- 強關聯案例的地理尺度差異很大——從「一條坡道」（清水寺、鹿港）到「一整座古城」（清邁，此時建議按子區域再分組，避免稀釋）到「跨城市多日路線」（Camino，性質已超出「單一地標周邊」範疇）。策展分組的**邊界大小**本身也是一個需要依案例判斷的變數，不是固定半徑或固定地點數。

## 8. 結論與對資料模型的啟示

**清水寺這批地點適合表達為「有主題敘事的策展關聯」，而非純地理鄰近呈現**——同一條坡道動線、同屬法定傳統建造物群保存地區、共享清水寺門前町起源敘事、體驗節奏天然互補，四項判準全部成立。

但案例研究同時顯示：**這種強關聯是特例，不是常態**。同樣「地點群聚」的表象下，實際關聯強度差異極大（0/4 到 4/4 都有真實案例），且即使關聯強，其**性質**（參拜動線／貿易史／資源導向／多重身份堆疊／廣場放射）也不該套用單一敘事模板。

對應回前期討論的三個資料模型方向：

- **方向 B（鬆散分組/策展主題標籤）不該無差別套用在所有 Attraction 上**——只有通過四項判準檢驗（建議 2 項以上）的地點群，才值得建立策展分組；建立前應該先做類似本文的實地判斷，而非假設「鄰近就該分組」。
- **方向 C（純地理鄰近查詢）作為底層能力應該保留**——即使某地點群通過了策展判準、建立了 B 型分組，使用者「我人在這附近，還有什麼」的即時情境仍需要 C 這種動態鄰近查詢，兩者是互補而非互斥的兩層呈現，不是二選一。
- 群組的**命名/敘事框架不該寫死成單一模板**（如強制套「XX老街散策」）——資料模型若要支援 B，策展主題本身應該是自由文字/敘事類型欄位，讓不同性質的地點群（參拜動線、貿易史、廣場區塊、多日路線）各自表達貼切的敘事語感，而非被迫套進同一種命名句式。
- 群組的**地理邊界/範圍認定**需要人工判斷，不建議用固定半徑自動生成——清邁案例顯示範圍過大會稀釋關聯強度，適合按子區域細分；Camino 案例顯示範圍過大甚至會超出「單一地標周邊」的產品定位，性質上更接近另一種功能（多日路線規劃）。

## 9. 附：介面呈現試想

呈現方式的視覺化試做（強調「鄰近關係一眼可見」＋「精選原因清楚」兩項需求）以 Artifact 形式產出，用清水寺周邊真實的 11 個地點資料試做三個方向：

1. **[坂道繪卷](https://claude.ai/code/artifact/be3eecb4-b03f-4873-aea9-9a1d0cce07d8)** — 動線隱喻：以坡道為縱向卷軸，精選點依真實位置掛在兩側，燈籠光暈呼應 App 既有暖色光暈；傳達「同一條路」但不強制排順序。
2. **[門前選帖](https://claude.ai/code/artifact/7e8065ed-683e-4094-9adc-4a3696898570)** — 雜誌編輯式：「一句話精選理由」作大標、店名退居署名位，鄰近關係交給頂部一維坡道帶（與清單 hover 連動）。
3. **[散策羅盤](https://claude.ai/code/artifact/b014e8ac-98e3-4f8c-bf07-48fd12eb5797)** — 鄰近雷達：以清水寺為圓心、同心圓是徒步分鐘，點位落在真實方位，與衛星卡片雙向連動，沿用 tripace 地圖紙感色系（`#EDE6DA`／暖沙 `#C4956A`）。

**推薦方向：散策羅盤**——同時最直接回答兩個需求：同心圓讓「鄰近」變成可讀的分鐘數，卡片讓精選理由常駐可見；視覺語彙也與現有地圖最接近，最容易落地。可吸收「門前選帖」的「理由優先」文案寫法作為卡片文案規格（大標是精選理由、店名退居署名位，而非店名當大標、理由當附註）。
