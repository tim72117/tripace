# override.md

補充 SKILL.md「判斷是否破壞性」的規則，不取代原本的判斷方法，只是額外釐清一種容易誤判的情況。

## CLI 介面才是破壞性判準

本專案的公開介面是 **CLI 子命令的呼叫方式**（旗標名稱、必填/選填、輸出格式），不是它底層打的內部 API 端點本身。

判斷是否破壞性時：

- **CLI 子命令的呼叫方式有更動**（新增/移除/改名旗標、改變必填規則、輸出格式不相容）→ 破壞性，按 SKILL.md 既有規則升版。
- **CLI 底層呼叫的內部端點（`/internal/*`，需登入）回應形狀改變，但 CLI 呼叫方式本身不變、且呼叫端在同一次異動中同步更新** → 不算破壞性。這類端點只給自家前端/CLI 用，不是對外公開的相容性承諾對象，即使回應 JSON 結構改變，也不會讓任何外部呼叫端「打新版端點壞掉」——因為外部本來就打不到、也不該打這些端點。

判斷順序：先看有沒有動到 CLI 子命令本身的呼叫方式；沒有的話，即使底層端點/資料結構有變動，也先當作非破壞性處理，除非另有明確理由（例如該端點其實有外部呼叫端、或改動影響到資料正確性而非單純形狀）。
